## Tooling changes I made to tools/bank/check.py
The tests (`tests/py/test_bank.py`, 19) pass. Every other `checked` file in new/p4, p5 and p6 gives the same check result as before the changes.
1. **Marks for OR questions.** If ICAI prints marks beside an OR alternative as well as beside the question it replaces, that extra marks line no longer counts as a missing item. Someone has since built a sums/alt_left extension on top of this.
2. **Lone numbers inside a page.** `clean_page` used to drop every line holding only a number anywhere on the page, because the page-number shape "#" counts as a running foot. That removed stacked-fraction denominators. Now it drops the other running heads and feet first, then a lone number only if it is the first or last line left. This matches the function's own docstring.
3. **MTP Part I marks.** check.py now recognises "carry N Marks each". MCQ items with those marks no longer show as "items only".

## Remaining tooling issues (not fixed)
- check.py expects a question number on the answer side. ICAI's past-paper Suggested Answers do not print one there, so every past paper needs `accept:` lines for its question numbers.
- check.py does not read case `label:` text, so headings with digits ("Case Scenario 1 [MCQs 1-3]") need `accept:` lines.
- The word check does not expand ligatures in the PDF text.
- The full `build.py` failed a few times on other agents' draft files (unknown tags, `marks: none` without a note). Retrying a minute later worked.
