## Tooling problems
1. **check.py changed under me.** It was rewritten at 15:57 while I was on t-164. My first run on that file reported 14 differences: the furniture numbers 1, 3 and 2019, plus phantom mismatches on 15,000 and 0 in the EOQ formulas. Running the same file again under the new version gave 0 problems.
2. **`build.py --check` writes no data.** `tools/shot.sh` shows "Question not found" for a new document until a full `.venv/bin/python build.py` runs. I ran three full builds, which rewrite the shared data/; all were green.
3. **Accept semantics are loose.** An accepted number covers its largest shortfall in any one page group, not its total. A number accepted once can therefore hide another real miss of that number in another group.
4. **MCQ numbers that restart need hand accepts.** check.py counts an MCQ number once per side across all m-keys, so documents that restart MCQ numbering per group always need them.
5. **Minor:**
   - The long labels ("Integrated Case Scenario-1, MCQ 1") make wide buttons in the question navigator. This is cosmetic.
   - seg.py text still shows the raw private-use bullet glyph (U+F0B4 and others) in some pages, though `--info` says they are mapped. It caused no number problems.
